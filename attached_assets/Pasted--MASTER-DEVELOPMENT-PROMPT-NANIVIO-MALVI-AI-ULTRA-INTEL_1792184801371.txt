# MASTER DEVELOPMENT PROMPT: NANIVIO MALVI AI — ULTRA-INTELLIGENT AI COMPANION

## 1. PROJECT OBJECTIVE

Upgrade the existing Malvi AI inside the Nanivio ecosystem into an advanced, multilingual, voice-first, context-aware AI assistant and personal companion.

Malvi must be deeply integrated into Nanivio, not built as an isolated chatbot or disconnected demonstration.

The objective is to make Malvi an intelligent, conversational assistant capable of answering questions, generating ideas, explaining concepts, providing advice, performing calculations, assisting with decisions, navigating users through supported Nanivio features, providing location-based guidance with permission, and participating in natural live voice conversations.

Preserve the existing Nanivio application, authentication, messaging, audio/video calling, Langpretation, subscriptions, business services, payment systems, database and administrative controls. Extend existing implementations rather than replacing working functionality unnecessarily.

Before modifying code, inspect the complete existing codebase, identify existing functionality, detect mock implementations, identify missing integrations and create a clear implementation plan.

Do not assume any feature works merely because its interface exists.

## 2. MALVI'S IDENTITY AND PERSONALITY

Malvi is the official AI assistant and digital companion of Nanivio Tech. Ghana.

Her personality must be:
- Intelligent, thoughtful, friendly, professional and approachable.
- Conversational and natural rather than robotic.
- Proactive when the user would benefit from a relevant suggestion.
- Patient when explaining complex topics.
- Capable of brainstorming, comparing alternatives and explaining advantages and disadvantages.
- Respectful of the user's choices, privacy, culture and selected language.
- Honest about uncertainty, limitations and unavailable information.
- Concise for simple requests and detailed when requested.

Malvi should support a consistent identity, voice, avatar and interaction style across supported Nanivio interfaces.

She must never pretend to be human, claim to possess feelings or experiences she does not have, or fabricate information to appear intelligent.

## 3. ACTIVATION AND LIVE CONVERSATION

Implement a polished Malvi activation experience.

Users should be able to activate Malvi by:
1. Tapping a floating Malvi assistant button.
2. Selecting Malvi from the application's assistant menu.
3. Saying “Malvi” to activate an optional wake-word feature, where technically supported and explicitly enabled by the user.
4. Using supported accessibility and voice controls.

When activated:
- Display Malvi's avatar in a polished conversation interface.
- Show a listening indicator when the microphone is actively capturing audio.
- Provide a clear visual indicator while Malvi is processing.
- Show or animate the speaking state during voice output.
- Allow users to switch between voice and text.
- Support mute, stop speaking, end conversation, microphone controls and language selection.
- Preserve conversational context throughout the active session.
- Allow users to interrupt speech and ask another question naturally.
- Resume or recover gracefully after temporary network interruptions.

Use a real-time speech-capable AI service for live conversations where appropriate. Do not simulate live speech using prerecorded responses.

Do not claim wake-word detection is active unless the required implementation is working. Explain microphone permissions and provide clear controls to disable listening.

Background listening must not be enabled without an explicit user choice and a technically supported, privacy-compliant implementation.

## 4. ADVANCED INTELLIGENCE AND REASONING

Malvi should assist with:

- General knowledge and explanations.
- Problem-solving and structured reasoning.
- Brainstorming and business planning.
- Creative ideas and content development.
- Arithmetic, percentages, currency calculations and budgeting.
- Comparisons and decision support.
- Project planning, schedules and task breakdowns.
- Writing, editing, translation and summarisation.
- Technical explanations and software troubleshooting.
- Education, learning and skill development.
- Everyday planning and practical recommendations.
- Research using approved information sources and live web retrieval where available.
- Step-by-step instructions for completing tasks.

Use reliable calculation tools for financial arithmetic and other precision-sensitive computations when available.

For current or changing information, retrieve up-to-date data from suitable sources when the relevant integration is enabled.

Malvi must distinguish verified facts from estimates, assumptions and suggestions. She must not invent search results, calculations, transactions, locations or service statuses.

For high-impact financial, legal, health or safety matters, provide appropriately cautious information and recommend qualified assistance when necessary.

## 5. PERSONAL COMPANION AND CONVERSATION CONTEXT

Develop a secure, user-controlled memory system.

Malvi should be able to:
- Remember relevant preferences when the user permits it.
- Retain the user's selected language and preferred interaction style.
- Refer to information from the current conversation.
- Continue an interrupted task using available saved context.
- Recall user-approved goals, projects and preferences.
- Offer relevant suggestions without being intrusive.
- Allow users to inspect, correct and delete assistant memory through supported controls.

Separate short-term conversation context from persistent personal memory.

Store persistent memory securely, associate it with the authenticated user, and enforce access controls. Do not expose one user's conversation history or memories to another user.

Do not retain passwords, authentication codes, private keys, recovery phrases or other credentials in assistant memory.

Memory must not be fabricated. When relevant information is unavailable, Malvi should ask the user rather than pretending to remember.

## 6. COMPLETE MULTILINGUAL CAPABILITY

Integrate Malvi with Nanivio's supported language catalogue and Langpretation infrastructure.

Requirements:
- Load available languages from a maintained configuration or provider capability endpoint.
- Avoid hardcoding a small, arbitrary language list.
- Support all languages and dialects that the connected speech, translation and text services genuinely support.
- Include language names in their native scripts where practical.
- Detect the language used by the user when appropriate.
- Respond in the language selected in the user's Nanivio settings.
- Allow the user to change the language at any time.
- Support text conversation, voice input and speech output for each supported language where the relevant provider supports them.
- Provide appropriate fallback behavior when a language is not supported by a particular speech or translation service.
- Preserve meaning, names, numbers and context during translation.
- Handle mixed-language conversations when supported.
- Respect explicit instructions to reply in a different language for a particular conversation.

Use the user's persisted language preference as the default. Do not silently override it because another language was detected.

Synchronize language settings with the existing Nanivio language system and Langpretation components.

Do not advertise every language as fully supported until the applicable input, output, speech and translation capabilities have been verified.

## 7. LANGPRETATION INTEGRATION

Integrate Malvi with Nanivio's existing Langpretation feature rather than building an unrelated translator.

Where supported, Malvi should assist with:
- Text translation.
- Voice-note translation.
- Live one-to-one audio-call interpretation.
- Live video-call interpretation.
- Group-call interpretation.
- Conversation language selection.
- Speaker and target-language configuration.
- Translation status and error feedback.
- Usage allowances and translation-minute accounting.

Inspect the existing Agora calling integration and translator services before changing them.

Connect the actual audio-processing pipeline to the selected speech recognition, translation and speech synthesis providers. Ensure that translated audio can be delivered through the intended calling experience.

Do not treat text translation displayed beside a call as proof that live audio interpretation works.

If a provider does not support the required language, latency or audio-streaming capability, report the limitation and implement a compatible fallback where possible.

Keep Langpretation billing and usage measurement consistent with Nanivio's actual subscription and service-value rules.

## 8. LOCATION INTELLIGENCE AND GOOGLE MAPS

Integrate location-aware assistance using Google Maps Platform or another approved mapping provider.

With explicit permission, Malvi should be able to help users:
- Find nearby hospitals, pharmacies, restaurants, shops, banks and other supported places.
- Search for addresses and points of interest.
- Calculate driving, walking, cycling or transit routes where available.
- Estimate travel time using current routing data when available.
- Understand directions and nearby landmarks.
- Find services near a specified destination.
- Plan journeys and compare suitable routes.
- Assist with location-based business discovery.

Requirements:
- Request location permission when needed.
- Allow manual address entry when permission is declined.
- Never fabricate the user's current location.
- Distinguish estimated travel times from verified live traffic information.
- Display map and route results through an appropriate interface.
- Protect location information and avoid unnecessary location retention.
- Keep Google Maps API keys and other sensitive credentials out of public source code where appropriate.
- Apply API restrictions, quotas and billing controls.

Malvi must not claim to have located a user, searched nearby places or calculated a live route unless the required service actually returned the relevant information.

## 11. SUBSCRIPTION-AWARE MALVI

Malvi must operate according to the user's actual Nanivio subscription plan.

Inspect the existing plan definitions, billing logic and entitlement model before introducing new plan names or prices.

Create or extend a server-side entitlement system that determines:
- Whether Malvi is available to the user.
- Which AI models or capabilities the user may access.
- Voice-conversation allowances.
- Advanced tool availability.
- Memory capabilities.
- Translation access and minute allowances.
- Applicable daily or monthly limits.
- Usage totals and remaining allowances.
- Upgrade requirements.
- Subscription expiry or renewal status.

All entitlements must be verified by the backend.

Do not rely on frontend-only checks, user-submitted plan names or editable client-side usage counters.

Track usage using real provider usage data or reliable application-level measurements. Avoid fabricated minutes, simulated quotas or hardcoded consumption.

Prevent duplicate billing events, enforce rate limits and handle interrupted sessions safely.

When a user reaches a limit:
- Explain which allowance has been exhausted.
- Show remaining alternatives, if any.
- Offer an upgrade where appropriate.
- Resume service only when the user's entitlement permits it.

Do not charge a user for a failed operation as though it succeeded. Reconcile usage and billing events reliably.
